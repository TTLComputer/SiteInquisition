# Changelog

## Unreleased

- **Four work areas instead of fourteen screens.** The navigation now follows an investigation: **Traffic** (requests, browser, timeline, live connections), **Explore API** (endpoints, resources, values, fields, API files, GraphQL, technology), **Replay** (open editors, flows, compare, auth and negative tests) and **Overrides** (everything that changes live traffic). **Project settings** (capture scope, session and authentication, proxy, certificates, storage, integrations) and **Advanced tools** (decode, race, protocol lab, script console) sit in the footer. Coverage moved out of History into Explore API, Endpoints; variables, login macros and AWS signing moved out of Cookies into Project settings, Session and authentication. Old names still resolve, so every link, shortcut and contextual action lands on the page that now owns it. Navigation never enables, disables or reorders a rule.
- **Overrides, Active** lists every mock, match and replace rule, breakpoint and live hook in one table, with whether it is on and how often it matched, a switch for each, and Edit to its own editor.
- Drop a Traffic row on Replay in the navigation to open it in an editor. Coming back to an area opens the page last used there.

- **Build requests without raw editing.** Replay's request now has Params, Headers, Body and Auth views next to Raw, all over the same text. Values are decoded as far as they go (a query parameter that is url › base64 › JSON with an encoded field inside opens as editable JSON, a base64 header of form fields opens as rows, Cookie and Authorization split into their parts) and encoded back the same way on edit; untouched values stay byte for byte.
- **Import curl**: paste a curl command into the Replay editor, use Import curl, or press + on the tab bar. Bash and Windows cmd copies from browsers both work; files the command reads are asked for in Body.
- **Multipart and file bodies**: edit multipart parts as fields and attached files, send a file as the whole body, and edit captured uploads with their files attached. `{{file:name}}` puts a file's bytes in a body (an attachment, or a file in the project folder).
- **OAuth 2.0 profiles**: authorization code with PKCE through the built-in browser (the redirect back is answered for you), client credentials, password and refresh token grants, endpoint discovery, and `{{oauth:name}}` tokens that refresh themselves before a send.

- **Precise request matching**: rules, mocks and breakpoints can match an exact path, a path template, glob or regex, a list of methods, and any number of conditions on query parameters, headers, cookies, JSONPath values, GraphQL operation names, types, root fields or persisted query hashes, and body text (=, contains, starts/ends with, glob, regex, exists, absent, number comparisons, any case, not). Response rules can test either side of the exchange. Mock and Break from the Inspector now use the exact path. Conditions are checked when saved, so a bad JSONPath or regex is reported in the editor.
- **Decode in place, everywhere**: select any value in the Inspector (bodies, headers, the request line, WebSocket and MQTT payloads), the Replay editor and response, or a WS Replay message, and choose Decode (or press Ctrl D) to see it decoded right where it was, in heavier, tinted type. A chip next to the selection says what it found (base64 › json, jwt, url...) before you click, with Decode as to pick the chain yourself. Selection is smart: a caret on a value takes the whole value, a JSON string's content decodes the string and replaces it with the decoded JSON lined up with its line, and spaces and trailing commas are dropped. Regions nest: decode inside a decoded value to go another layer down.
- In Replay and WS Replay, decoded regions are encoded again on send, byte for byte when untouched; a region holding tokens is encoded after the tokens are filled in (the sender sees an `{{encode:...}}...{{/encode}}` block). Click a region (or put the caret in one) for Show encoded or Encode back, Always decode, Codecs and Copy.
- Decode in place also works in the Streams composer (payload and handshake), the breakpoint editor, Race and HTTP/3 lab requests (encoded again when sent), and in read-only text: Codecs layers and result, cookie values, session cookie payloads, decoded Socket.IO and SignalR frames, MCP approval arguments and script results. Editors take Ctrl D directly.
- Always decode saves the JSON field (and any decoded fields around it) as a field codec. Saved field codecs now show as decoded regions in the Inspector's Pretty view and open as regions in Replay, instead of a separate Decoded fields view and the Fields box. Ctrl Shift D (and the Codecs buttons) still open the selection in Codecs.
- **HTTP/2 in transparent mode, decided by the server.** Cleartext HTTP/2 with prior knowledge is served (straight to the port or in a tunnel) and passed on as prior knowledge; a server that refuses it gives a 502 rather than a silent switch to HTTP/1.1. An `Upgrade: h2c` offer (curl `--http2` on `http://`) goes to the server instead of dropping the connection; if it accepts, the HTTP/2 connection is relayed untouched and its streams recorded (rules and breakpoints do not apply there). Over TLS the client is offered the protocol the server picked by ALPN, including a refusal. TLS sent straight to the port goes to the port in Host or `:authority` rather than always 443. HTTP/2 keeps trailers and `te: trailers`, so gRPC passes through.
- **Save signing keys to the project**: a signing key used to be held for the session only. Now that the project database is encrypted, each key has a **Save** checkbox (in Settings › Signing keys, and when adding one): a saved key is kept in the project, sealed with the master key from the OS keyring — the same protection as saved identities — so it survives restarts and is ready to share with the project. Keys not marked Save still stay in memory and never touch disk, and saving is offered only when a keyring is available to encrypt it. A saved key referenced by an evergreen `{{sign:name}}` token keeps that token working across sessions.
- **Re-sign tokens, and keep them evergreen**: a clear **Re-sign** button now sits on any JWT or framework session cookie wherever it shows up — the Cookies jar, the Codecs workbench, and the Inspector's JWT panel. Edit the claims or payload, sign with a key from the key store (or a secret typed in place), and copy the result. The same panel can register the token as **evergreen**: with a known key, SiteInquisition re-mints it fresh on every send — its `exp` pushed forward and `iat`/`nbf` refreshed — so a captured token never goes stale.
- Reference an evergreen token anywhere with `{{sign:name}}`: in a Replay header, a match-and-replace rule (so it reaches proxied traffic), a login macro or a flow. Bind one to a cookie and the jar and proxied requests send the freshly-signed value automatically. The new **Cookies › Signed tokens** tab lists them, their refresh window and bound cookie, and mints a preview on demand.
- Works for JWTs (HS/RS/PS/ES/EdDSA, via the key store) and Flask session cookies today; the key store note explains the binding. AWS SigV4 replays already re-sign with fresh credentials each send, so they stay evergreen on their own.
- **WebSocket replay**: Send to Replay on a WebSocket (the Replay pill, Ctrl R, the Inspector, the Streams header) opens a WebSocket Replay tab instead of the bare upgrade request. The captured connection is written out as an editable handshake and a list of steps: send a message (text or binary, one frame or any frame preset), wait for the server (any message, text or /regex/, with a timeout and an optional value saved into a variable), exact frames, and close. Run opens a new connection and runs the steps; the connection stays open to keep sending, every run is kept so you can step between runs and diff the server's messages with the original, and the steps show how each one went.
- WebSocket messages take Replay tokens (`{{var:x}}`, `{{cookie:session}}`, `{{counter:1..5}}` sends one message per value, flows), fresh cookies on the handshake, an Encode chain, and Fields that encode JSON fields inside Socket.IO and SignalR framing too. Saved field codecs open those fields decoded. Decode selection (Ctrl D) round-trips a message through Codecs.
- Socket.IO keep-alive: replays answer Engine.IO pings (and send EIO 3 client pings), and leave heartbeats out of the steps and waits. SignalR record separators show as ␞ so they survive editing.
- **WebSocket message breakpoints**: a breakpoint can pause WebSocket messages (from the client, the server or both, optionally only those containing some text or matching a /regex/) on connections through the proxy. Paused messages wait in Rules, Breakpoints to be forwarded, edited (as text or base64) or dropped; later messages on that side wait behind them, and pings still go straight through. The record marks edited messages (with the original) and dropped ones. Without such a breakpoint the relay is byte for byte as before. Break on messages is in the Inspector and the WebSocket Replay tab.
- Agents and scripts: MCP tools `websocket_script` and `replay_websocket`, and `siq.websocket.script()` / `siq.websocket.run()` in scripts.
- Fixed: a text whose tokens had been checked by `hasTokens` could lose its batch tokens (the shared regex kept its position).

- **Codecs shows every nested layer**: under the outer chain, the Chain view lists each JSON field that holds more encoded JSON, indented by depth, with its own codecs. Any layer can be kept encoded, and any can be saved as a field codec.

## 1.0.0-beta.1

The first beta, for Linux (x64) and Windows (x64). Packages: a .deb for Debian and Ubuntu, a .tar.gz, and a portable .zip for Windows.

**This is a beta.** Expect rough edges, and keep a copy of any project you care about.

- **Windows is untested on a real Windows machine.** The build passes its tests and a start-up smoke test on GitHub's Windows runners, but nobody has used it on a Windows desktop yet. Reports are welcome.
- **The builds are not signed.** Windows SmartScreen will warn that the app is from an unknown publisher: choose More info, then Run anyway. Unzip the portable .zip anywhere and run `SiteInquisition.exe`; nothing is installed.
- On Linux, install the .deb with `sudo apt install ./siteinquisition_1.0.0-beta.1_amd64.deb`, or unpack the .tar.gz and run `siteinquisition`.

**Capture**: an HTTP/1.1 and HTTP/2 proxy (plain, CONNECT and SOCKS5 on one port), HTTPS interception for in-scope hosts with a per-install CA, HTTP/3 for the built-in browser, WebSocket capture, and an MQTT 3.1/3.1.1/5.0 relay. A built-in Chromium browser records on its own listener. Scope rules decide what is decrypted and recorded.

**Finding things**: a searchable SQLite store with a filter language, History with saved views, a site map and live follow, a Timeline, endpoint coverage, technology detection, server-error flagging, JWT, session cookie, AWS and CSRF awareness, and decoders for Socket.IO, SignalR, ViewState, protobuf and gRPC.

**Changing things**: Replay with tokens, fresh cookies and CSRF tokens and SigV4 signing; Race; match and replace, mocks and breakpoints; a codec workbench; Streams composers for WebSocket and MQTT; scripts and test suites; login macros, variables, flows; API files (OpenAPI, Swagger, Postman, HAR, GraphQL) with contract checks, an auth matrix and negative tests.

**Agents**: an MCP server, over stdio (`siq mcp`) or HTTP, with approvals for actions that change things.

**Safety and housekeeping** (from the pre-release review):

- Scripts run in a separate, killable process, sandboxed by default with Node's permission model. Each script can turn its sandbox off; that is trusted per computer, so shared projects ask again. Agents' scripts always run sandboxed and always ask.
- Large bodies stream through the proxy: only the first 10 MB (by default) of a body is kept, and bodies over 64 MB skip hooks instead of filling memory.
- Listeners bind to 127.0.0.1 unless `--lan`; with it, each new device waits for your approval.
- The CA key and saved identities are encrypted with a key in the OS keyring when there is one. New CAs last two years; `siq ca rotate` and `siq ca remove`.
- Delete traffic by selection, by search or all at once, with retention by age and size. Project files are private to your user.
- Settings warns when the project is not on an encrypted disk.

**Windows**: a portable zip with `SiteInquisition.exe` and `bin\siq.cmd`. Secrets use DPAPI for your user, Settings checks BitLocker, and the CA guide covers the Windows certificate store. The exe is not code signed and has Electron's icon for now.

- **Field codecs**: say a JSON field is, for example, base64 of JSON (`$.payload = base64>json`). The Inspector shows it decoded, Replay opens it decoded and encodes it on send, and Codecs can save one from a field it decoded.
- **Codecs decodes all the way down**: a JSON field that holds more encoded JSON (a JSON string, base64 of JSON, url-encoded, and so on) opens up in place, at any depth. The result re-encodes as you type, through every layer, and a value sent from Replay is updated there as you edit, so there is no Encode or Put back step. An untouched value comes back byte for byte.
- **Search inside requests and responses**: text now matches any part of a word, ignoring case (`PO-77`, `csrf_tok`), and can be narrowed to one side or part: `req:`, `res:`, `reqbody:`, `resbody:`, `reqheader:`, `resheader:`. Existing projects are re-indexed once when opened.
- **Build search** in History: pick where to look and what for, see how many requests match as you go, and search. Starts from what is already in the filter.
- **Search matches are highlighted** in the Inspector, which scrolls to the first one; Previous and Next step through the rest.
- **Cookies**: Decode opens the value in Codecs with its layers detected. Reading a framework session cookie moved to its own Session button.
- **Send to Replay** looks and reads the same everywhere, and every list of recorded requests has it.
